# GURT — notes for Claude

GURT (GURT Universal Repository Thingy) installs any distro's packages on any distro.

- `gurt` — the whole CLI, one bash script (`set -euo pipefail`). `GURT_VERSION` at the top is what releases tag.
- `app/` — the app (`gurt gui`), the GURT Setup Wizard (`--wizard`) and GURTd (`--daemon`): one native Rust program, `gurt-app`, on egui/eframe (glow, X11 + Wayland). `data.rs` reads gurt's files (`gurt __paths`, the recipes' `.gurtinfo`, the db), `jobs.rs` runs gurt and is sudo's askpass (the app re-runs itself with `--askpass`, over a 0600 unix socket), `skin.rs` + `widgets.rs` are the six skins and the hand-painted controls, `tabs.rs` / `dialogs.rs` / `wizard.rs` the UI, `sound.rs` the synthesized sounds + music (piped to paplay / pw-cat / aplay), `daemon.rs` GURTd. Packages ship `/usr/lib/gurt/gurt-app-{x86_64,aarch64}` (`tools/build-app.sh`: cargo-zigbuild against glibc 2.28); `gurt gui` finds it (`gui_bin`) or downloads the release's (`gui_fetch`, checked against `SHA256SUMS`). `GURT_APP_TAB` / `GURT_APP_SRC` / `GURT_APP_SILENT` / `--size WxH` are for screenshots.
- `site/index.html` — gurtproject.org, one static page (GitHub Pages, deployed by `.github/workflows/ci.yml`).
- `packages/<name>/GURTBUILD` — Main GURT recipes; `dirt/` is the opt-in 18+ repo. `.gurtinfo` files are generated by CI.
- Main GURT is mostly free software. The license decides (`foss_class` in `gurt`, `foss_class` in the app, `fossOf` on the site; keep the three in sync): closed-source apps are labeled and listed after the free ones, `gurt foss on` blocks them. New Flathub recipes (`tools/gen-flathub.py`) are free software only.
- ChromeOS: `is_cros` = Linux on ChromeOS (Crostini, a Debian container); `$CROS_NATIVE` = ChromeOS itself (Chromebrew, `PM=crew`, only `/usr/local` writable: the DB lives there, `cros_relocate` moves packages under it, `asroot` runs without sudo).
- NixOS: `$NIXOS` (`/etc/NIXOS`; `GURT_NIXOS=1` fakes it) sets `PM=nix`. `nix/` is nixpkgs into the user's profile (`nix_install`, `nix_meta` evaluates version / free / description). On NixOS, Main GURT prefers nixpkgs, other distros' packages install into /usr like anywhere else (no box; nix-ld runs them), `nixos_paths` puts `/usr` + `/usr/local` on PATH and nix-ld's library path via `/etc/profile.local`, and `nixos_needs` prints the `configuration.nix` line for system services.
- Sources: binary repos (apt dnf zypper pacman apk xbps eopkg gentoo) sync into one TSV index each (`sync_source`, `idx_file`); `gh/` (`gh_install`, a wrapper key that remembers the `inner` package), `pip/` `npm/` `cargo/` (`lang_install`, packed as real .gurt files), `nix/`, `brew/`, `flatpak/`, `snap/` are tracked with `record_meta`. A new source goes in `norm_src`, `install_any`, `remove_pkg`, `find_outdated`, `search_foreign`, `cmd_info`, the completions, the app's `#srcs` and the site's `SRC`.
- `gh-only.map` (`category|owner/repo|name|desc`): free apps that ship on GitHub releases. `gurt gh-only` lists them, `gh/<name>` installs one, the app and the site show them on the gh/ tab, CI runs `gurt gh-only --check`. Shipped next to `vibes.map` (install.sh, make-setup-wizard.sh, the pages job).
- Hotwyr (`gurt hotwyr`, alias `gurt hook`): shell functions (bash/zsh/fish, written by `hook_script`, sourced from ~/.config/gurt/hotwyr.*) wrap the typed package manager commands and `sudo <pm>`, and call `gurt __pmhook` (real PM first; on a not-found install, `hook_find` offers a gurt spec) and `gurt __cnf` (command not found; exit 200 = nothing found, the shell's own handler runs). `main` skips option parsing for `__pmhook` / `__cnf` so the PM's flags pass through.
- nullglob is on in `gurt`: an empty glob passed to `ls` lists the current folder, so use `newest_first`.
- Native first: a Flathub / Snap recipe installs your distro's package of the same app when there is one (`native_for`: the recipe's `native_<pm>=` / `native=` (`no` turns it off), the AppStream catalog's package for the Flathub id, or the same name whose distro homepage belongs to the Flathub id's project, `appid_home`: org.gimp.GIMP ↔ gimp.org), recorded as `distro:<pkg>` (removed by `pm_remove`, updated by system updates). `gurt native off` (`$NATIVE_CONF`) turns it off.
- Package packs: `packs.map` (`id|name|what it's for|apps`, Main GURT names only, CI checks them; shipped next to `vibes.map`). `gurt pack [list | show <id> | <id> --skip a,b]` (`cmd_pack`; each app installs in its own subshell so one failing doesn't stop the rest), `data::packs` + pack buttons in the app's Setup tab and the wizard's starter apps, `renderPacks` on the site (the pages job copies packs.map next to it).
- GURT keys: `keys.map` (`sha256("gurt-key:"+KEY)|unlocks|note`, shipped next to `vibes.map`) maps a key's hash to what it unlocks (`app:<recipe>`, `skin:gold`, `track:shanty`, `ach:<id>`); never put a plaintext key in the repo except the easter eggs, obfuscated (`gurt quack`, the site's Konami code). `gurt redeem` writes `~/.config/gurt/keys`, `key_unlocked` / the app's `State::has` read it. Dev builds have everything; `gurt __keygen` (dev, unlocked) makes keys and backs the app's dev-only "make a key" button. A new unlock goes in `KEY_UNLOCKS` + `key_what` in `gurt` and `KEY_UNLOCKS` in `app/src/app.rs`.
- `tools/` — `lint.sh` (recipes), `make-setup-wizard.sh` + `win/` (installers), `make-logo.py` (logo + inline SVG), `make-badge.py` ("Get now on gurt" badge); `render-logo.js` makes their PNGs.

## Checks before pushing
- `shellcheck -S warning gurt install.sh tools/lint.sh tools/make-setup-wizard.sh tools/win/build-exe.sh`
- `./tools/lint.sh` after touching a recipe (recipes must never call sudo/doas).
- `cd app && cargo build --release` (and no new warnings) after touching the app
- UI changes: the site in headless Chromium (`/opt/pw-browsers/chromium`, Playwright); the app under Xvfb (`xvfb-run`, `--size 390x800` etc, `import -window root` for a screenshot; xdotool needs `windowfocus` first to type). 390 / 768 / 1280px, every skin, look at the screenshots.

## UI rules (anti-slop) — app and site
GURT is a dense, utility-first package tool. It must not look like a generic SaaS template. The site: plain CSS only, custom properties on `:root`, one `:root[data-skin=…]` block per skin. The app: the same tokens live in `skin.rs` (`Pal`), and every control is painted in `widgets.rs`, so a skin's look is code there, not egui's default widgets.

**Palette**
- No soft gradients, glows, blurs or glassmorphism (`backdrop-filter`, blurred `box-shadow`, `text-shadow` glow). No indigo/violet/purple "AI" accents.
- One flat accent per skin (GURT: yellow `#ffc629`) for interactive and selected states. Everything else is greys plus the semantic colors `--good` / `--bad`.
- The only multicolor allowed in the GURT skin is the hard-edged 4-block brand stripe (red / yellow / green / blue, hard stops) and the logo.

**Shape**
- Corners: `var(--r)` (2px) or square. Never pill shapes (`999px`) and never big radii (≥ 8px) on boxes, buttons or chips. Round only things that are physically round (status dots).
- Borders: 1px solid `var(--edge)`. Boxes are separated by borders, not by shadows or whitespace.
- No offset or drop shadows on boxes, buttons or dialogs. State changes are mechanical: border color, fill, or an inset/pressed look. No hover lifts, scale, bounce or float.

**Type and density**
- Prose in the system sans. Data in monospace (`--mono`): package names, versions, sources, commands, chips, nav, buttons and field labels. Headings are sentence case at a readable size. No eyebrows: no small uppercase letter-spaced labels above or instead of headings.
- Dense: tight padding (about 6–10px), small gaps. Package lists are left-aligned rows (name | description | actions), not airy symmetric card grids.
- No emojis as icons anywhere in the app or the site: tabs, buttons, chips, headings, cards and dialogs are text. A control that needs a symbol uses a typographic one (✓ ✗ → ×), never an emoji. Text that comes from gurt or recipes goes through `noEmoji()` before it's shown. App logos are images, not emoji: Flathub's icon (or a recipe's `icon=`), then the app's desktop icon from the user's system (`/appicon/<name>` in the app), then a letter tile. (The `gurt` CLI's own output can keep its emojis.)

**Layout**
- Asymmetric and left-heavy: the list or main content on the left, controls and parameters in a narrow column or on the right.
- Forms are compact aligned columns: label above or beside the field, no oversized cards around each field.
- Dialogs: square, 1px border, a title row with a bottom border, then content.

**The site's front page** is terminal-first, in GURT's own colors and logo (never openSUSE's name, logo or chameleon): a dark navbar, a dark hero (logo, headline, a demo terminal that types out real gurt output with tabs, the 20-source chip strip and the Linux downloads under it, and a narrow right column "Other Operating Systems" with Windows and ChromeOS as folding panels; your system's panel gets the accent and opens), the features as dense rows, and a dark footer with link columns. It's the one roomy part. Everything else on the site (the package browser, Build your setup, dialogs) follows the dense rules above.

**Skins** (`gurt`, `win11`, `xp`, `w95`, `vapor`, `hacker`) share this structure, but each keeps its own identity through fonts, borders, title bars and how its controls look (bevels, brackets, underlines), not just different colors. A new skin must change more than variables.
