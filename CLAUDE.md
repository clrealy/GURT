# GURT — notes for Claude

GURT (GURT Universal Repository Thingy) installs any distro's packages on any distro.

- `gurt` — the whole CLI, one bash script (`set -euo pipefail`). `GURT_VERSION` at the top is what releases tag.
- `gui/gurt-gui.py` — the app: a local Python server plus one inline HTML/CSS/JS page (`PAGE`). No frameworks, no build step.
- `site/index.html` — gurtproject.org, one static page (GitHub Pages, deployed by `.github/workflows/ci.yml`).
- `packages/<name>/GURTBUILD` — Main GURT recipes; `dirt/` is the opt-in 18+ repo. `.gurtinfo` files are generated by CI.
- `tools/` — `lint.sh` (recipes), `make-setup-wizard.sh` + `win/` (installers), `make-logo.py` (logo + inline SVG).

## Checks before pushing
- `shellcheck -S warning gurt install.sh tools/lint.sh tools/make-setup-wizard.sh tools/win/build-exe.sh`
- `./tools/lint.sh` after touching a recipe (recipes must never call sudo/doas).
- `python3 -m py_compile gui/gurt-gui.py`
- UI changes: open the app/site in headless Chromium (`/opt/pw-browsers/chromium`, Playwright) at 390 / 768 / 1280px in every skin, check for sideways scroll and overlaps, and look at screenshots.

## UI rules (anti-slop) — app and site
GURT is a dense, utility-first package tool. It must not look like a generic SaaS template. Plain CSS only: custom properties on `:root`, one `:root[data-skin=…]` block per skin.

**Palette**
- No soft gradients, glows, blurs or glassmorphism (`backdrop-filter`, blurred `box-shadow`, `text-shadow` glow). No indigo/violet/purple "AI" accents.
- One flat accent per skin (GURT: yellow `#ffc629`) for interactive and selected states. Everything else is greys plus the semantic colors `--good` / `--bad`.
- The only multicolor allowed in the GURT skin is the hard-edged 4-block brand stripe (red / yellow / green / blue, hard stops) and the logo.

**Shape**
- Corners: `var(--r)` (2px) or square. Never pill shapes (`999px`) and never big radii (≥ 8px) on boxes, buttons or chips. Round only things that are physically round (status dots).
- Borders: 1px solid `var(--edge)`. Boxes are separated by borders, not by shadows or whitespace.
- No offset or drop shadows on boxes, buttons or dialogs. State changes are mechanical: border color, fill, or an inset/pressed look. No hover lifts, scale, bounce or float.

**Type and density**
- Prose in the system sans. Data in monospace (`--mono`): package names, versions, sources, commands, chips, nav, buttons, field labels and section headings (small, uppercase, letter-spaced).
- Dense: tight padding (about 6–10px), small gaps. Package lists are left-aligned rows (name | description | actions), not airy symmetric card grids.
- Emojis only as functional anchors (📦 🛡 🎰 🔁), at most one per control. Don't decorate headings with them.

**Layout**
- Asymmetric and left-heavy: the list or main content on the left, controls and parameters in a narrow column or on the right.
- Forms are compact aligned columns: label above or beside the field, no oversized cards around each field.
- Dialogs: square, 1px border, a title row with a bottom border, then content.

**The site's front page** follows opensuse.org's layout in GURT's own colors and logo (never openSUSE's name, logo or chameleon): a dark navbar, a dark hero with one card per platform (your system's card gets the accent), a feature grid, and a dark footer with link columns. It's the one roomy part. Everything else on the site (the package browser, Build your setup, dialogs) follows the dense rules above.

**Skins** (`gurt`, `win11`, `xp`, `w95`, `vapor`, `hacker`) share this structure, but each keeps its own identity through fonts, borders, title bars and how its controls look (bevels, brackets, underlines), not just different colors. A new skin must change more than variables.
